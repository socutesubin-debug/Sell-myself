# 포트폴리오 설명글: 매체별 형식

같은 프로젝트라도 매체마다 분량과 구조가 다르다. 긴 것(VIN 케이스 스터디)을 먼저 쓰고, Behance와 PDF는 그 글에서 **줄여서** 만든다. 줄일 때 새 사실을 더하지 않는다.

공통으로 먼저 채울 프로젝트 사실(비어 있으면 물어본다):

- 프로젝트명, 기간, 형태(개인/팀/외주/수업/공모전)
- 팀 구성과 **내 역할**(내가 직접 한 작업 목록)
- 문제 또는 목표: 왜 시작했나
- 과정: 리서치, 시도한 안, 버린 안과 이유
- 결과: 숫자, 피드백, 수상, 출시 여부. 없으면 "결과 없음"도 정보다
- 사용한 툴
- 공개해도 되는 범위(회사 프로젝트면 NDA 여부)

## VIN 케이스 스터디

> 참고: VIN의 실제 페이지 구조와 글자수 제한은 이 kit에 확인돼 있지 않다. 아래는 일반적인 케이스 스터디 구조다. 사용자가 VIN 화면 구성이나 제한을 알려주면 이 절을 그에 맞게 고친다.

- 분량: 섹션당 300~600자, 전체 1500~3000자(공백 포함). 제한이 있으면 그것을 따른다.
- 기본 말투: 이야기하듯.
- 구조:
  1. 한 줄 요약: 무엇을 누구를 위해 만들었고 결과가 무엇인지
  2. 개요: 기간, 역할, 팀, 툴 (짧은 목록 허용)
  3. 문제: 출발 상황과 왜 문제였는지
  4. 과정: 리서치와 핵심 결정 2~3개. 결정마다 "왜 이렇게 했나"
  5. 결과: 숫자 또는 정성적 결과, 내 기여 범위
  6. 돌아보며: 다시 한다면 바꿀 점 (사용자가 말한 것만)
- 각 섹션 사이 `[이미지: 무엇을 보여줄지]` 자리 표시.
- 헤딩은 짧게("문제", "과정"). "X: Y" 부제 헤딩을 반복하지 않는다(humanizer C-10).

## Behance

- 분량: 프로젝트 설명 200~500자(공백 포함). 이미지 사이 캡션은 각 1~2문장(50~100자).
- 기본 말투: 담백하게.
- 구조:
  1. 프로젝트 설명(상단): 무엇, 누구를 위해, 내 역할, 기간을 2~4문장
  2. 이미지별 캡션: 이 화면에서 무엇을 결정했는지 한 문장
  3. 크레딧: 팀원·역할 (사용자가 준 이름만)
- Behance는 해외 사용자도 본다. 영어 버전이 필요한지 묻고, 필요하면 한국어 최종본을 기준으로 옮긴다(영어판에 새 내용 추가 금지).

## PDF 포트폴리오

- 분량: 프로젝트 1개당 1~3페이지, 페이지당 텍스트 150~300자(공백 포함).
- 기본 말투: 담백하게.
- 구조(페이지 단위로 나눠서 쓴다):
  - 표지 페이지: 프로젝트명, 한 줄 요약, 기간·역할·툴
  - 본문 페이지: 페이지마다 제목 한 줄 + 설명 2~3문장 + `[이미지: …]`
  - 결과 페이지: 결과 한두 줄
- 레이아웃에 들어갈 텍스트라 짧은 개조식을 허용한다(humanizer J-1, J-3은 칼럼·리포트 기준이므로 여기선 과하게 적용하지 않는다). 다만 항목마다 굵은 머리말을 붙이지 않는다.
